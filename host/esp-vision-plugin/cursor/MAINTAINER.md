# Cursor plugin adaptation

Reviewed the [official plugin guide](https://cursor.com/docs/plugins) and [plugin reference](https://cursor.com/docs/reference/plugins) on 2026-10-27. Cursor accepts both the Agent Plugins root `plugin.json` standard and the richer `.cursor-plugin/plugin.json` format. This adapter exports the latter, with explicit Skill and MCP paths, the official relative logo, a fixed credential-free Knowledge URL and the unchanged CLI/license closure. No hooks, variables, device MCP or client configuration edits are needed.

Build from the repository root using Node.js 22+ after staging the current Core via `node tools/ci/mcp/install_host.mjs --output <project-local-source-sdk-directory>` and building `npm --prefix host/esp-vision-plugin run build`. Then run `npm --prefix host/esp-vision-plugin run build:cursor -- --output-dir <absolute-project-local-output-directory>`. Keep output outside the plugin source and set TMPDIR/TMP/TEMP under the project temporary root. The builder refuses overwrites, symlink templates and outputs inside source (including aliases), records full source SHA and payload hashes in BUILD-PROVENANCE.json, and emits a SHA-256 sidecar. Local source must be clean and committed for a source-bound review candidate. CI validates the full CI_COMMIT_SHA and needs no Git executable.

GitLab `plugin_checks` exports review candidates for one month. GitHub's `Plugin release packages` workflow builds the release-tag source and attaches the checked Cursor ZIP/checksum to the corresponding GitHub Release alongside WorkBuddy and QoderWork. A missing Release becomes a draft. Preserve existing assets/notes; identical files are reused and conflicts fail. See the plugin README's Release distribution section. The Cursor semver follows the shared plugin version; increment it before public updates. These attachments do not publish a Cursor marketplace listing.

The official local test path is `~/.cursor/plugins/local/esp-vision/`, containing the actual complete plugin, followed by a reload and Customize verification. A symlink to an external repository is skipped by Cursor. Respect Allow Local Plugin Imports (off by default for Enterprise), preserve existing copies, and account for same-name marketplace installs taking precedence. Do not claim activation based on ZIP or CLI smoke tests. Verify actual Skill use, Knowledge connection/tool use, retained CLI resources and a user-authorized device workflow in the target Cursor version before public submission.

Cursor expands CURSOR_PLUGIN_ROOT in documented MCP command/args/env/cwd fields. That does not guarantee it exists in arbitrary agent terminal sessions, so the Skill locates the current installation instead of assuming shell substitution. Windows paths retain the shared PowerShell/MSYS guidance.

Official marketplace submission is a public Git repository link at https://cursor.com/marketplace/publish, not a ZIP upload. Publish the verified exported payload as the root of the distribution repository, with its committed logo, README, CLI and licenses; the firmware source checkout alone lacks the generated CLI and is not a complete marketplace payload. Do not add a monorepo marketplace entry pointing at an incomplete source directory. If distribution later uses multiple plugins in one public repository, add its documented root `.cursor-plugin/marketplace.json` with unique names and valid relative sources. Any repository publication or marketplace submission is separate from this offline build and requires user authorization. No marketplace listing, account eligibility or target-host acceptance has been established by this change.

The platform `plugin.json` is only an overlay on the root shared identity; it is not an installable manifest. Common payload/provenance/archive mechanics live in `scripts/export-common.mjs`. Device policy and diagnostics come unchanged from the shared Skill/reference; add platform differences here rather than copying those rules. See the plugin README shared-source table.
